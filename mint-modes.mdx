title: 'Mint Modes Explained'
description: 'Scheduled, Manual, Gas Monitor, Dry Run, and MEV Tip: what each one does'
---

After picking a stage/phase (or, for Custom Contract, after setting up calldata), you'll see a mode menu like this:

```
Mode:
  A - Scheduled   (auto at stage open)
  B - Manual      (mint now)
  C - Gas Monitor (mint when base fee < base_gwei)
  W - Watch       (poll for the mint to open, then mint immediately)
  D - Dry run     (simulate only)
  E - MEV Tip     (coinbase tip, multi-builder)
  F - Batch Tip   (single-transaction bundle)
  ⌂ - Main Menu
```

## A - Scheduled

**Use when:** you know roughly when the drop opens and want the bot to handle the exact timing for you.

The bot counts down to the stage's start time, showing a live `Opens in MM:SS...` timer. This is the mode most people want for a normal drop.

## B - Manual

**Use when:** the drop is already open (or you want to try minting right now, with no waiting).

Submits immediately for every eligible wallet, in parallel. If `gas.gas_limit` is set to `0`, it first repeatedly tests the transaction until the contract accepts it (see the `gas.gas_limit` note in [Configuring the Bot](/configuration#gas-settings)), useful if you're not sure the mint has actually started yet.

## C - Gas Monitor

**Use when:** the drop is open (or about to be) and you want to wait for cheaper gas before minting, rather than paying whatever the network charges the instant it opens.

The bot waits for the stage to open, then checks the network's base fee every 30 seconds and mints as soon as it drops below your configured `gas.base_gwei` threshold.

This mode always compares against `gas.base_gwei`, even if `gas.mode` is set to `rapid`. If you leave `base_gwei` too low, the bot may wait for a long time and miss the mint phase. Set `gas.base_gwei` to a realistic threshold before using this mode, see [Configuring the Bot](/configuration#gas-settings).

## W - Watch

**Use when:** the project hasn't announced an exact start time, and minting is turned on manually by the team instead of on a schedule.

<Note>
  Custom Contract mode only.
</Note>

The bot checks the contract itself for a sign that minting has opened, for example a switch the project's team flips when they're ready, instead of counting down to a clock time. As soon as it detects that switch, it mints right away.

<Tip>
  Every contract differs, some expose nothing at all. The bot shows what it finds and lets you confirm before starting, or you can enter one yourself.
</Tip>

## D - Dry run

**Use when:** you want to double-check everything is configured correctly with zero risk.

Prints which wallets and RPCs would be used and stops. No transaction is built, signed, or sent. Nothing costs gas or ETH.

## E - MEV Tip

**Use for:** highly competitive mints where you're racing other bots for the same block, and you're comfortable paying extra to improve your odds.

This mode pays a tip (`bundle.tip_eth`) directly to block builders to try to get your mint transaction prioritized. If your tip is too low compared to competing bots, your bundle simply won't land, with no error beyond "Bundle did not land within max_blocks." Size your tip deliberately, see `bundle.tip_eth` in [Configuring the Bot](/configuration#bundle--mev-settings).

<Note>
  Only available when minting on Ethereum mainnet.
</Note>

## F - Batch Tip

<Warning title="Advanced feature">
  This mode requires [Bundling Tools](/bundling-tools) setup, a deployed contract and delegated wallets. If you're not comfortable with those concepts, use one of the other modes above instead.
</Warning>

**Use for:** minting from a group of wallets as one single transaction, instead of one transaction per wallet.

Once set up, pick **F - Batch Tip** here like any other mode.

One wallet (`bundle.tip_wallet`) funds the entire batch, every wallet's mint cost plus the tip. Make sure it's funded before you start. See `bundle.tip_wallet` in [Configuring the Bot](/configuration#bundle--mev-settings).

Gas scales with how many wallets are in the batch, a large batch can cost a lot of real ETH in gas alone, on top of the mint price. See `bundle.gas_limit` in [Configuring the Bot](/configuration#bundle--mev-settings).

The coinbase tip (`bundle.tip_eth`) only does anything on Ethereum mainnet. On every other chain, the bot ignores it automatically, no need to change your config when switching chains.

<Note>
  OpenSea and Custom Contract only. Only appears in the mode menu for a chain where you've completed the [Bundling Tools](/bundling-tools) setup. On OpenSea, only for public phase. On Custom Contract, not available when using per-wallet parameters.
</Note>

## Spam Mode

Optional, off by default. Applies to Scheduled, Manual, Gas Monitor, Watch, and Batch Tip. Not available for MEV Tip.

Instead of sending one transaction per wallet, the bot sends several, spaced a few milliseconds apart, to improve your odds of landing the mint if a single attempt would lose the timing race. Turn it on with `spam_mode: true`, see the `spam` settings in [Configuring the Bot](/configuration#spam-mode).

Not available on Verse.Works, regardless of mode.

<Warning>
  Blocked on Ethereum mainnet, since a failed attempt still costs gas there and spam mode expects some attempts to fail.

  Also needs a very good RPC. A public one usually starts to rate limit and reject requests quickly, see [RPC Setup](/rpc-setup).
</Warning>

<Note>
  Terminal only. Spam mode is ignored if you start a mint from Telegram, see [Telegram Remote Control](/telegram-control#limitations).
</Note>
